## 3. 実装確認結果(依頼の確認項目ごと)

### 3.1 ゲスト利用 — 一致
- アカウントなしで主要機能が利用できる(`app/(tabs)`、アカウント未設定ビルドの表示「ゲストとして通常どおり利用できます」: `src/features/auth/create-account-screen.tsx`)。
- データはローカル SQLite(`expo-sqlite`)とアプリ内画像保存。サーバー送信はアカウント作成後。

### 3.2 メール・Apple・Google 認証 — 規約・ポリシーに未記載
- メール:登録時にメール確認が必須(`requireEmailVerification: true`)。確認・再設定リンクは1時間有効(`api/src/email.ts`)。
- Apple:`expo-apple-authentication`、`usesAppleSignIn: true`。Google:iOS クライアント ID 設定時のみ有効(`GOOGLE_CLIENT_IDS`)。
- アカウント自動連携は無効(`accountLinking.enabled: false`)。
- ❓`account` テーブルは access / refresh / id トークン列を持つ。ソーシャル認証時にこれらを実際に保存するかは未確認(Better Auth の既定動作に依存)。保存する場合はポリシー記載か保存しない設定を検討。

### 3.3 ローカル SQLite / D1 / R2
- SQLite:ローカルが Primary Store(ARCHITECTURE)。
- D1:同期対象は `api/src/sync/entities.ts`(folders / notes / questions / goals / settings / study_sessions / answer_history / review_history / fsrs_states ほか)。D1 は画面表示の直接の Source of Truth ではない。
- R2:ノート画像。キーはアカウント別(`u/<userId>/`)、公開アクセスなし(`wrangler.toml`)。許容形式は jpeg/png/gif/webp/heic、最大 15 MB。
- ログ:`wrangler.toml` に `observability` 設定は見当たらない(Workers ログの保存は未確認)。

### 3.4 アカウント削除・データ削除・保存期間
- `api/src/account/service.ts` の `deleteAccount`:削除依頼を記録 → R2 の `u/<userId>/` を削除 → D1 の `user` 行を削除(`session` / `account` / `sync_*` / `image_objects` は ON DELETE CASCADE)→ R2 を再掃除。失敗時は再試行で完了(冪等)。
- 日次 Cron(`17 3 * * *`)で削除済みアカウントの R2 残骸を再走査(経過 7 日まで毎回、90 日まで週1、以降は月1。打ち切らない)。
- アプリ側(`src/features/account/account-card.tsx`)の確認文:アカウント情報・クラウドのデータ・クラウド上の画像・この端末のそのアカウントのデータと画像を削除、ゲストのデータは削除されない。ログアウトでは削除されない。
- 保存期間:
  - セッション 30 日(`auth.ts`)、確認・再設定トークン 1 時間。
  - 同期データはアカウント削除まで。削除済みレコードの論理削除(`deleted_at`)は残り、**物理削除(期間経過後の消去)の処理は確認できませんでした**。ARCHITECTURE.md も「物理削除のタイミングは同期設計時に決定する」としたままです。
  - お問い合わせ・Web アクセスログ・Cloudflare 側のバックアップ/ログの保存期間は、リポジトリから確認できません。

10. 未成年者の利用、課金(Phase 9 の内容次第)、特定商取引法に基づく表記。
