## 3. 実装確認結果

### 3.1 ゲスト利用・通知・画像アクセス
- ゲスト:ローカル SQLite(`expo-sqlite`)とアプリ内画像保存。アカウント作成前にサーバーへ送信する処理はない。
- 画像:`ImagePicker.launchImageLibraryAsync`(PHPicker)で利用者が選んだ画像のみを受け取る(`src/features/notes/note-image-store.ts`)。ライブラリ全体の走査はしない。`app.json` の `photosPermission` 文言は残っているが、選択のみなら権限要求は不要(コメント記載)。
- 通知:`expo-notifications` はローカル通知のみ。`getExpoPushToken` / `getDevicePushToken` の呼び出しはなく、サーバーへ送る処理はない。
- 位置情報・連絡先・広告識別子・解析・広告・クラッシュレポートの SDK:`package.json` に依存なし。リリースビルドの最終確認は §7。

### 3.2 認証(`api/src/auth.ts`)
- メール:メール確認必須。確認・再設定リンクは 1 時間(`TOKEN_TTL_SECONDS`)。登録済みメールでの再登録時は本人へ通知メールを送信。
- Apple / Google:アプリがネイティブ SDK で取得した ID トークンのみを受け付ける(リダイレクト方式は拒否)。アカウント自動連携は無効。
- **保存される認証情報(node_modules の Better Auth の実装とアプリのクライアントコードで確認):** サインイン時に `account.id_token` へ ID トークンが保存される。アプリは `idToken.token` と `nonce` のみ送信しており、`accessToken` / `refreshToken` は送信しないため、通常これらは保存されない(`account` テーブルに列はある)。ポリシーには ID・メールアドレス・名前・ID トークンのみ記載した。パスワードはハッシュ値(`account.password`)。
- セッション:`session` に IP アドレスと User-Agent を記録。有効期間 30 日(`expiresIn`)。
- レート制限:`rate_limit` テーブル(D1)にキーと回数・時刻を記録。キーは IP を含む(Better Auth の既定)。

### 3.3 ローカル SQLite / D1 / R2
- ローカル SQLite が Primary Store。同期対象は `api/src/sync/entities.ts`(folders / notes / questions / goals / settings / study_sessions / answer_history / review_history / fsrs_states ほか)。
- 同期データは D1 の `sync_records` に JSON(`data`)と `deleted_at` で保存。競合時は複製を残す設計。
- 画像:R2。キーは `u/<userId>/`。公開アクセスなし(`wrangler.toml`)。

### 3.4 アカウント削除・保存期間(`api/src/account/service.ts`)
削除の流れ(`deleteAccount`):削除依頼を記録 → R2 の `u/<userId>/` を削除 → 進行中の画像アップロードがあれば中断(`DeletionPendingError`。再試行で完了) → D1 の `user` 行を削除(`session` / `account` / `sync_*` / `image_objects` は ON DELETE CASCADE。`verification` と `rate_limit` の該当行も削除) → R2 を再度掃除して完了を記録。R2 削除に失敗した場合は `user` 行を残し、利用者の再実行で続きから完了する。

- **非同期・再試行:** 完了後の R2 の最終掃除に失敗しても利用者へはエラーにならず、日次 Cron(`17 3 * * *`)の `sweepDeletions` が再実行する。完了済みのアカウントも、経過 7 日までは毎回、90 日までは週 1、以降は月 1 回、R2 のプレフィックスを再走査する(打ち切りなし)。`sweepCleanupTasks` が中断アップロードの残骸を処理する。→ ポリシーでは「完了を無条件に保証しない」「画像の削除は繰り返し確認する」と記載し、再走査の間隔は記載していない。
- **削除対象外:** `account_deletions` テーブルに、`user_id`・要求/完了/走査時刻・失敗回数が残る(削除記録。利用者の個人情報は含まないが、`user_id` は残る)。ポリシーには記載していない(§7 の確認事項)。
- **ローカル:** 削除を実行した端末は、サーバー削除の成功後に `requestLocalPurge` でそのアカウントの DB と画像を削除(失敗時は次回起動で再試行。`src/db/local-purge.ts`)。**ほかの端末のローカルデータは遠隔削除されない**(次回同期は API が拒否する)。ゲストの DB・画像は削除されない。ポリシー・規約に明記した。
- **保存期間(実装と照合):**
  | 項目 | 値 | 場所 |
  | --- | --- | --- |
  | セッション有効期間 | 30 日 | `auth.ts` `session.expiresIn` |
  | 確認・再設定リンク | 1 時間 | `TOKEN_TTL_SECONDS` |
  | 画像アップロードのリース | 10 分 | `UPLOAD_LEASE_MS`(内部値。記載していない) |
  | 掃除タスク保持 | 7 日 | `CLEANUP_GRACE_MS`(内部値。記載していない) |
  期限切れのセッション・検証レコードを物理削除する処理は確認できていない。ポリシーでは有効期間のみ記載し、記録の消去時期は断定していない。
- **削除済みレコード(同期の墓標):** `sync_records.deleted_at` を付けて残し、**期間経過後に物理削除する処理は存在しない**(`DELETE FROM sync_records` はなし)。ARCHITECTURE.md も「物理削除のタイミングは同期設計時に決定する」のまま。ポリシーでは「アカウント削除まで保持。内容を含む場合がある」と事実のみ記載。
- **ログ:** `wrangler.toml` に `observability` 設定なし。アプリは個人情報を含まないエラーログのみ出力(`console.error`)。Cloudflare 側の保持期間は確認できない。
- **バックアップ:** D1 の復元機能(Time Travel など)・R2 の保持は Cloudflare の仕様に依存。ポリシーには「残る場合がある」とのみ記載し、期間は断定していない。

## 6. 法的判断が必要な項目

1. 規約第5条:同期機能の終了時の事前通知・データ取り出しの猶予。
2. 規約第7条第4項:免責の有効範囲(消費者契約法第8条など)。
3. 規約第8条:重要な変更の通知方法(アプリ内通知は未実装)と、定型約款の変更要件(民法548条の4)。
4. 規約第10条:個人運営で住所非公開の場合の専属的合意管轄と、消費者との関係での有効性。
5. ポリシー3・4章:Cloudflare・Resend への「委託」が第三者提供に当たらないという整理。Apple・Google を委託先としない整理(ポリシー本文は「各社のポリシーに基づいて取り扱う」と記載)。
6. **国外での取り扱い:** 外国にある第三者への提供(個人情報保護法28条)に必要な情報提供(所在国、当該国の制度、委託先の措置)を満たすか。現状のポリシーは「日本国外で取り扱われることがある」とのみ記載しており、不足する可能性がある。Cloudflare(米国)・Resend(米国)・Apple・Google が対象。
7. 電気通信事業法の外部送信規律の対象性。
8. ポリシー7章:保存期間を具体的に記載する必要性、削除済み同期データ(墓標)を無期限に保持することの妥当性、ほかの端末に残るデータの説明の十分性。
9. ポリシー8章:IP アドレス・User-Agent・`account_deletions.user_id` の位置づけ。
10. 会員登録時の規約同意の取得方法。
11. 未成年者の利用、課金、特定商取引法に基づく表記(氏名・住所の「請求があれば開示」の可否を含む)。

## 7. 運営者が確認すべき事実

1. Cloudflare D1 / R2 の保存ロケーション(ジュリスディクションの設定)。
2. D1 の復元機能・R2 の保持により、削除後にデータが残る期間。Workers ログ(Cloudflare ダッシュボード側)の設定と保持期間。
3. 削除済みの同期データ(墓標)を物理削除する運用を設けるか。設けない場合の保持をポリシーに残すか。
4. 期限切れの `session` / `verification` / `rate_limit` の消去運用。`account_deletions` の保持方針。
5. お問い合わせ内容・Web アクセスログの保存期間(リポジトリから確認できず、ポリシーでは「利用目的の達成に必要な期間」としている。具体的な期間を決めるか)。

7. リリースビルドに解析・広告・クラッシュレポートの SDK が含まれていないこと(現状の `package.json` では確認できた)。
8. アプリのログイン状態は Keychain(`expo-secure-store`)に保存される。ポリシー5章の Cookie の記載(Web サイト限定)のままで差し支えないか。
